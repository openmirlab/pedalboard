# Deterministic VST3 automation fixture

This is a diagnostic plugin built directly against the vendored VST3 interfaces.
It deliberately avoids JUCE's plugin wrapper so the fixture can consume every
`IParamValueQueue` point rather than accidentally testing a wrapper that discards
sample offsets. The source is GPL-3.0-only; SDK files retain their existing license.
No binaries are committed or installed in system plugin folders.

Run `uv run pytest tests/test_vst3_automation.py -q` from the repository with its
native extension installed. The session fixture builds into pytest's temporary
directory using CMake and a C++17 compiler. A missing toolchain fails the tests;
the diagnostic VST suite is not silently skipped. macOS, Windows and Linux layouts
are generated by CMake; only the macOS arm64 build has been verified locally.

Sixteen classes share the same nonconsecutive VST3 ParamIDs:

- **Automation Probe** consumes ordered points with the SDK's linear interpolation.
- **Automation Probe Last Point** deliberately ignores intra-block positions.
- **Automation Probe Delayed** returns audio delayed by20 reported samples.
- **Automation Probe Instrument** is note-gated and has no audio input. It emits
  note-offs after processing, detecting accidental host feedback of returned MIDI
  when chunk buffers are reused.
- **Automation Probe Infinite Gain** displays `-inf` at zero gain and uses a linear
  SDK plain model, exercising the validated display-parser path for dB curves.

- **Automation Probe Rate Dependent** changes its frequency maximum to Nyquist
  during format preparation, verifying that Hz curves use the prepared model.
- **Automation Probe Delayed Instrument**, **Long Delayed Instrument** and
  **Huge Delayed Instrument** gate notes before delays of 20, 4097 and 16385
  reported samples. The processor rejects blocks larger than the prepared
  capacity, exposing oversized latency-drain calls.

**Automation Probe Buses** adds independently visible main/external-key inputs
and main/auxiliary outputs, including mono/stereo asymmetry. Its routing DSP uses
`main * 0.25` when the external key exceeds0.5, otherwise passes main unchanged;
auxiliary output is half the original main. `NativeBusHost` loads this same
binary through the SDK factory and processes without Pedalboard/JUCE. The bus
tests first validate that native positive control, then require exact Python-host
audio. Invalid native calls are checked by the SDK host.

`tests/test_instrument_latency.py` uses these classes for offline compensation,
raw-stream preservation, near-end notes and source-clock curves. Its optional
original-bass integration runs when `PEDALBOARD_TEST_BASS_PLUGIN` points to the
separately built TactusBass VST3; no binary or private source is required by the
deterministic fixture suite.

Gain displays-60..12dB and frequency displays20..20000Hz with a logarithmic mapping.
The ordinary audio oracle is `float(input * pow(10, gain_db/20) * frequency_hz/20000)`;
normalized controls are rounded to float32 like the existing host. The instrument
uses a constant input of1 while a note is held; it is a timing diagnostic, not a
synthesizer intended for listening. The infinite-gain variant uses a0..2 linear gain.
A bypass accepts0/1. The read-only Blocks display counts actual processor calls.
Broken and Misparsed exercise unavailable and dishonest conversion callbacks.

Analytical comparisons allow3e-7 absolute/relative float32 error; same-binary
partition/reset/held-target comparisons require exact equality. The last-point
fixture is expected to differ in `vst3_events` mode and match in default
`sample_steps` mode. This separates correct host delivery from plugin behavior.

**Audio MIDI** and **Delayed Audio MIDI** extend the bus diagnostic with a
note-gated main path, independent auxiliary output, gain/Hz curves and20-sample
main delay respectively. CC1 explicitly maps to the discrete bypass via
IMidiMapping; discrete targets do not interpolate. Returned notes transpose by
12 semitones; injected note-offs expose accidental output feedback. The SDK host
uses its own event/parameter containers (host_events.h), validates audio against
the intended oracle, and compares both audio and returned event positions against
Python hosting. Existing ten classes retain their behavior.

Clock, Meter, Loop and Position variants encode actual native ProcessContext
fields into four output channels. Position uses four 16-bit words for exact
signed 64-bit frames. NativeBusHost independently supplies clock contexts to the
same binary, with its own loop subdivision and a known-value positive control.
These observations verify delivery through the host, rather than Python getters.

Optional external tempo-DSP acceptance uses Steinberg's unchanged Sync Delay
example (VST SDK commit 3cdf9ca5d1f5b1b21e0a86832aa4abe55607bd96).
Build the SDK's sync-delay target with SMTG_CREATE_PLUGIN_LINK=OFF and
SMTG_RUN_VST_VALIDATOR=OFF, then set PEDALBOARD_TEST_STEINBERG_SYNC_DELAY to the
resulting bundle and run tests/test_hosted_transport.py. No SDK source/binary is
copied into this repository. Its default four-quarter-note wet delay must move
an impulse by int(60 / bpm * 4 * sample_rate) at 90/120 BPM, 44.1/48kHz and 31/8192
native spans. This tests an existing tempo-dependent algorithm, not a diagnostic
getter; it does not certify commercial vendor plugins or AU behavior.
